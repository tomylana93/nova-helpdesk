# Architecture

This starter kit is a standard Laravel + Inertia + Vue application with a few intentional **seams** that make it easy to extend a derived project without rewriting core code. This document orients you to those seams.

## Backend layering

| Layer | Location | Responsibility |
|-------|----------|----------------|
| **Controllers** | `app/Http/Controllers` | Thin HTTP entry points. Validate via FormRequests, delegate to Actions, return Inertia responses or redirects. |
| **Actions** | `app/Actions/**` | Single-purpose, invokable use cases (e.g. `MasterData/Users/CreateUser`, `Auth/ChangeUserPassword`). Business logic lives here, not in controllers. |
| **Tables** | `app/Tables/**` | Server-driven data-tables built on `AbstractTable` (query, filters, sorting, pagination → Inertia props). See [recipe-crud](recipe-crud.md). |
| **Policies** | `app/Policies` | Authorization (`UserPolicy`, `AdminSettingsPolicy`), backed by Spatie permissions. |
| **Settings** | `app/Settings` | Database-backed configuration via `spatie/laravel-settings` (`GeneralSettings`, `StyleSettings`, `PasswordSettings`). Each class is registered in `config/settings.php`. |
| **Concerns** | `app/Concerns` | Reusable traits (`HasOptions` for enum→select options, validation-rule traits). |
| **Enums** | `app/Enums` | Canonical, type-safe domain values (`UserRole`, `Permission`, `UserStatus`, `Site*`). |

## Form request → typed payload

FormRequests expose a `payload(): array` accessor with a strict `@return array{...}` shape. Controllers call `$request->payload()` (not `validated()`) so Actions receive precisely-typed input — this is what keeps PHPStan level 7 green. Do **not** name it `data()` (collides with `InteractsWithData::data()`).

## The RBAC seam — `config/roles.php`

Roles and permissions are **canonical enums** (`App\Enums\UserRole`, `App\Enums\Permission`), but the **role → permission map is data**, living in `config/roles.php`. The `permission:sync-roles` command (`SyncRolesCommand`) is the sole consumer: it creates every role/permission from the enums and applies the map.

A derived project changes its access model by editing the enums + this map — never the command. Baseline: `super_admin` (all), `admin` (manage settings + user management), `user` (none). See [recipe-rbac](recipe-rbac.md).

## Inertia shared props

`app/Http/Middleware/HandleInertiaRequests` shares to every page:

- `name` — site name from `GeneralSettings`.
- `locale`, `version`.
- `auth.user` + `auth.abilities` (e.g. `manage_settings`) for frontend nav-gating.
- `style` — `StyleSettings` (+ resolved `font_url`) for theme/font/layout.
- `branding` — resolved logo/icon URLs from `BrandingAssetResolver`.

Frontend types live in `resources/js/types/` (`auth.ts`, `settings.ts`). See [recipe-branding](recipe-branding.md).

## Locale (global)

A single source of truth: `GeneralSettings.site_locale`. The `SetApplicationLocale` middleware (registered in `bootstrap/app.php`) sets the app locale per request. Frontend strings are exported to JSON via `php artisan lang:export` and consumed by the `useTrans` composable. See [recipe-i18n](recipe-i18n.md).

## Scaffolding

Two generators speed up the common patterns (stubs in `stubs/`):

- `php artisan make:action <Name>` → `app/Actions/<Name>.php`
- `php artisan make:table <Name>` → `app/Tables/<Name>.php`

## Wayfinder

Typed route/action helpers are generated by `php artisan wayfinder:generate --with-form` and imported from `@/actions` / `@/routes`. The `--with-form` flag is **required** (the Vite plugin uses `formVariants: true`); the generated output is gitignored. Regenerate after changing routes, controllers, or actions.
