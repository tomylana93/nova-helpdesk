# Mirror Nova Starter Kit Design

## Goal

Bring `nova-helpdesk` up to date with sibling `nova-starter-kit` as closely as practical, while preserving helpdesk-specific domain code, dependencies, and project identity.

## Scope

This update mirrors shared project foundation pieces from `/home/tomylana93/projects/nova-starter-kit`:

- Composer dependency constraints and scripts where they are shared foundation concerns.
- Frontend package versions and ESLint import plugin migration.
- Static analysis and refactoring configuration.
- GitHub workflow shape, Dependabot configuration, and release-please configuration.
- Lockfiles after package updates.

This update does not blindly overwrite helpdesk-specific application files:

- Helpdesk routes, docs, config, models, migrations, pages, tests, and generated domain code stay intact.
- Dependencies that are referenced by helpdesk code stay installed even when the starter kit no longer has them.
- PHP stays at `^8.5` because `nova-helpdesk` already targets PHP 8.5 and CI uses PHP 8.5.

## Architecture

The project remains a Laravel 13, Inertia 3, Vue 3, Tailwind 4 application. The update is treated as a foundation synchronization, not a domain rewrite.

Configuration changes are copied or adapted from `nova-starter-kit` only when they represent current shared conventions. Where `nova-helpdesk` has additional needs, the starter-kit baseline is extended instead of replacing those needs.

## Dependency Strategy

Composer dependencies should move toward starter-kit constraints:

- Update `spatie/laravel-permission` to `^8.0`.
- Update `larastan/larastan` to `^3.9`.
- Keep helpdesk-specific packages including Media Library, Query Builder, Settings, Chisel, Excel, Debugbar, Pao, and other currently required packages.
- Keep `php` at `^8.5`.

Node dependencies should move toward starter-kit versions:

- Replace `eslint-plugin-import` with `eslint-plugin-import-x`.
- Update ESLint, Vue ESLint plugin, TypeScript, `vue-tsc`, Node types, and related tooling constraints to starter-kit values.
- Keep runtime packages used by helpdesk code, including charting, Echo/Reverb client packages, shadcn tooling, and icons when referenced.

Lockfiles must be regenerated by the package managers, not edited manually.

## Tooling Changes

`eslint.config.js` should switch from the `import` plugin namespace to `import-x`:

- Plugin key: `import-x`.
- Resolver setting: `import-x/resolver`.
- Rule names: `import-x/order` and `import-x/consistent-type-specifier-style`.

`phpstan.neon` should follow the starter-kit stricter baseline:

- Analyze `app/`, `bootstrap/app.php`, `config/`, `database/`, and `routes/`.
- Use level `7`.

`rector.php` should add starter-kit return type declaration rectors while preserving existing PHP 8.5 and Laravel Rector setup.

Composer scripts should follow the starter-kit layout:

- Add `types:check` for PHPStan.
- Make `test` run config clear, PHP lint check, Rector dry run, PHPStan, and tests.
- Make `ci:check` run frontend lint/format/types and Composer test.
- Preserve any helpdesk-only script that is still intentionally used, unless it conflicts with release-please.

## CI and Release

GitHub workflows should mirror starter-kit conventions:

- Use current checkout and setup-node action versions from the starter kit.
- Use Node 24 and PHP 8.5.
- Generate Wayfinder routes before frontend checks where needed.
- Run frontend format/lint checks in quality workflow.
- Run build, PHP type analysis, frontend type analysis, and tests in test workflow.

Release automation should mirror starter-kit pre-release and stable release flow:

- Add release-please workflow.
- Add `release-please-config.json`, `release-please-config.dev.json`, `.release-please-manifest.json`, and `.release-please-manifest.dev.json`, adapted to this repository name and current version source.
- Add Dependabot configuration for GitHub Actions.

Existing `version.json` should not be deleted unless the implementation confirms the starter-kit release-please setup has fully replaced that mechanism and no application code depends on it.

## Testing

The update is verified with the project finishing gate:

- `vendor/bin/pint --dirty --format agent`
- `pnpm run lint`
- `pnpm run format`
- `php artisan wayfinder:generate --with-form --no-interaction` only if routes, controllers, or invokable actions changed
- `composer ci:check`

If stricter PHPStan or Rector checks expose existing helpdesk issues, fix them when the fix is local and mechanical. Stop for developer review if the fix requires a domain or architectural decision.

## Risks

The highest-risk changes are the Spatie Permission v8 constraint, stricter PHPStan level 7 coverage, Rector return type rules, and release automation migration.

The implementation should avoid removing dependencies solely because the starter kit lacks them. Every removal must be backed by a local usage check.

## Out of Scope

- Redesigning helpdesk domain models or workflows.
- Replacing helpdesk UI screens with starter-kit screens.
- Changing authentication or authorization behavior beyond dependency compatibility.
- Editing generated Wayfinder files by hand.
